## Express Server
The server runs on Express 5 and Socket.IO 4 using Node 24:
- Factory `createServerInstance(overrides)` allows starting standalone instances with in-memory or file-backed SQLite databases.
- Bound by default to `0.0.0.0:3001` (configurable via `HOST` and `PORT`).
- `GET /health` continues returning HTTP 200 with phase status.
- Socket.IO CORS configured to match `CORS_ORIGIN` (defaults to permissive for local LAN development).

## SQLite Schema
Stored locally on host at `apps/server/data/relay-miden.sqlite` (or custom path via `DB_PATH`):
- `WAL` journal mode enabled for concurrent read/write performance.
- Foreign keys enabled.
- Tables:
  - `server_metadata`: Schema migration versioning and persistent `server_device_id`.
  - `devices`: Registered devices, protocol versions, application versions, and timestamps.
  - `tasks`: Canonical materialized projections (`id`, `revision`, `title`, `location`, `priority`, `status`, `action`, `created_by`, `state_hash`, `updated_at`, `deleted_at`).
  - `operations`: Append-only log with strictly monotonic `sequence INTEGER PRIMARY KEY AUTOINCREMENT`, unique `operation_id`, `task_id`, `actor_id`, and JSON payload.
  - `conflicts`: Audit records of concurrent branch collisions.

## Socket.IO Protocol
- Protocol version: `1` (`LAN_PROTOCOL_VERSION = 1`).
- Events:
  - `device:register` / `device:registered`
  - `sync:request` / `sync:operations`
  - `operation:submit` / `operation:accepted` / `operation:rejected`
  - `operation:broadcast`
  - `server:error`
- Runtime validation with Zod schemas in `@relay-miden/shared`.
- All operations are committed to SQLite before `operation:accepted` is returned or `operation:broadcast` is emitted.

## Device Registration
- Clients register with their persistent anonymous UUID from Phase 2.
- Server validates protocol version compatibility (`LAN_PROTOCOL_VERSION = 1`).
- Optional session token (`LAN_SESSION_TOKEN`) validated if configured on the server.
- Registered socket is mapped to the `deviceId`, preventing cross-device operation spoofing on open sockets.

## Initial Synchronization
- Client sends `sync:request` with its last known server sequence (`cursor`).
- Server queries `operations` table for sequence numbers greater than `cursor`.
- Bounded batches returned with `hasMore` and `totalServerOperations`.
- Client applies operations sequentially in IndexedDB and updates its local cursor.

## Real-Time Operation Propagation
- Local task creations and edits trigger `TaskOperationListener` in IndexedDB.
- If LAN is connected, client builds canonical `LanOperationPayload` (`TASK_CREATE` or `TASK_UPDATE`) and emits `operation:submit`.
- Server validates causal ancestry and state hashes via `SyncService`.
- Server commits transaction atomically, returns `operation:accepted` to sender, and emits `operation:broadcast` to connected peers.
- Peers receive broadcast, apply it via `applyIncomingLanOperation` using Phase 5 causal rules, and update reactive UI.

## Conflict Handling
- Server classifies updates using Phase 5 `classifyIncomingOperation`.
- If an update's base state hash does not match the server's current task state hash, server classifies it as `CONFLICT` and records it.
- Clients detect conflicts and store them in Dexie `conflicts` table.
- Users resolve conflicts via existing Keep Local / Accept Incoming UI.
- Resolution produces a transferable `TASK_RESOLVE` operation with `mergedOperationId` and `mergedStateHash` that converges both branches across LAN.

## Client LAN Service

## Known Limitations
- Physical LAN testing across two distinct hardware devices on a Wi-Fi router was not performed in this automated environment; integration was verified across isolated processes and browser contexts.
- HTTPS mixed-content: If the frontend is hosted on HTTPS, modern browsers may block unencrypted `ws://` or `http://` connections to local LAN IPs.
- Camera access over LAN IP HTTP is blocked by browsers; the app detects insecure contexts and falls back to image file upload.
- Automatic durable background retry queue, offline reconnection replay, and retry scheduling are Phase 7 capabilities. Phase 6 requires manual "Sync Now" or active connection during task mutation.
