## PaperBridge Protocol

- Protocol Identifier: `"RELAY_MIDEN_PAPERBRIDGE"`
- Version: `1`
- Message Type: `"TASK_CREATE"`
- Structure:
  ```typescript
  interface PaperBridgeEnvelope {
    protocol: "RELAY_MIDEN_PAPERBRIDGE";
    version: 1;
    messageId: string; // UUID v4
    messageType: "TASK_CREATE";
    senderId: string;  // Device UUID
    createdAt: string; // ISO 8601 UTC
    payload: PaperBridgeTaskPayload;
    checksum: string;  // 64-char lowercase hex SHA-256
  }
  ```
- Canonical serialization: Keys recursively sorted in Unicode order, `undefined` properties omitted, compact JSON format.
- SHA-256 Checksum: Computed over canonicalized envelope (excluding `checksum` field) via standard `crypto.subtle.digest`.
- Payload Budget: Strict 2,048 UTF-8 bytes ceiling (`MAX_PAPERBRIDGE_PAYLOAD_BYTES`). Tasks exceeding this budget are rejected with `OVERSIZED_PAYLOAD` with guidance on shortening text.

## QR Generation

- Engine: `qrcode` running client-side in the browser.
- Error Correction Level: Level `M` (~15% recovery) for optimal balance between data density and optical scan tolerance.
- Margins: 4 quiet-zone modules.
- Color: Brand Forest Green (`#004225`) on pure white background for maximum contrast.
- Export Options:
  1. Instant scannable on-screen display.
  2. Download as PNG image file (`relay-miden-task-[id].png`).
  3. Copy encoded raw JSON payload to clipboard.
  4. Regenerate unique message ID.

## QR Scanning

- Camera Engine: `html5-qrcode`.
- User Permission: Triggered strictly upon user interaction ("Use camera" button).
- Camera Preference: Rear-facing environment camera on smartphones (`facingMode: "environment"`).
- Insecure Context Detection: Detects HTTP on LAN IP addresses and informs users to use "Upload image" due to browser security restrictions on `getUserMedia`.
- Stream Cleanup: Immediately halts video feed upon detection and clears media tracks in `useEffect` cleanup upon unmounting or cancelling.

## QR Image Upload

- Decoding Engine: Client-side HTML5 Canvas pixel extraction + `jsQR`.
- Formats: PNG, JPEG, WebP.
- Multi-scale Fallback: Attempts native resolution followed by scaled down passes for high-resolution smartphone camera captures.
- Network Independence: 100% in-browser parsing; zero server uploads or external network requests.

## Task Import and Duplicate Handling

- Dedicated Import Path: Implemented `taskRepository.importPaperBridgeTask(envelope)`.
- Metadata Preservation: Preserves original remote task UUID, creator device UUID, creation timestamp, and revision number.
- Atomic Transaction: Enforces Dexie transaction across `tasks`, `operations`, and `imports` stores.
- Operation Ledger: Appends `TASK_IMPORT` operation with receiving device ID as actor and source `messageId` attached.
- Deduplication:
  1. Checks `imports` store for existing `messageId`: returns `status: duplicate` without creating duplicate tasks or operations.
  2. Checks `tasks` store for existing task ID with identical revision: registers duplicate import record and returns `status: duplicate`.
  3. Checks `tasks` store for differing revisions: protects local task and returns `status: conflict` (`REVISION_CONFLICT`).
  4. Checks for locally soft-deleted tasks: prevents silent resurrection and returns `status: conflict` (`TASK_DELETED_LOCALLY`).

## Security and Validation

- Schema Enforcement: Runtime Zod validation over envelope, task payload, quantity-unit parity, and string lengths.
- Integrity: Recalculates SHA-256 digest on canonical representation; rejects tampered or truncated data with `INVALID_CHECKSUM`.
- Clarity: SHA-256 is explicitly treated as accidental corruption/tamper detection, not cryptographic authentication or digital signatures.

- Single QR payloads are capped at 2,048 bytes to ensure reliable scanning on mobile camera viewfinders.
